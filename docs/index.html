What this measures — and what it does not

NINESCOPE tracks the tail of the CVSS distribution where a single unauthenticated request is enough: base score 9.0 and above. Two things are joined together — a feed of those vulnerabilities, and a scanner that works out which software a site is running so it can be matched against version ranges published by NVD.

1 · The vulnerability feed

Pulled from the NVD CVE API 2.0 by the server-side collector, filtered to base score ≥ 9.0, then merged with the CISA Known Exploited Vulnerabilities catalogue so each row is labelled with whether it is actually being exploited (and whether it is used by ransomware). The page never fabricates or extrapolates a row: every record is a CVE with a published NVD score.

2 · The stack scan is passive

  • One GET of the URL you supply, following redirects, with a normal user-agent.
  • Reads: response headers, cookie names, <meta name="generator">, script/stylesheet paths, framework markers in the markup, and the final hostname.
  • Does not: send exploit payloads, brute-force paths, guess credentials, enumerate ports, or attempt any modification. It cannot tell you a site is safe — only that no version it could fingerprint matches a critical CVE range.
  • Only versions that appear in the markup or headers can be matched. A site that strips its banners reports unversioned, which is not the same as clean.

3 · How a version is matched to a CVE

Each CVE's NVD configurations[].cpeMatch[] entries carry either an exact version or a range (versionStartIncluding, versionEndExcluding…). The index keeps those ranges for finger-printable products; the page compares the detected version against them with a numeric-segment comparator. A range with no bounds at all means the advisory names the product without pinning a version — those hits are flagged version-agnostic instead of being presented as a confirmed exposure.

Where a range closes with versionEndExcluding, that value is shown as the fixed version — it is the boundary the vendor set, not a guess.

4 · Known limits

  • Server-side plugins, themes and custom modules usually do not advertise a version, so the largest real-world attack surface on a WordPress site is the part this scan sees least.
  • Some sites front everything with a CDN and a WAF: you may fingerprint the CDN, not the origin.
  • A CPE product must be in the scanner's index for a match. Vendors that NVD names inconsistently ("php" vs "phpgroup:php") appear as separate keys; both are indexed where criticals exist.
  • CVSS 9.0+ is a severity floor, not a probability of exploitation. Cross-check the KEV chip before panicking about a score.
